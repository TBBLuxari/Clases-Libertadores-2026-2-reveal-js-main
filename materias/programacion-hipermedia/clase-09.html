Con los if el código aprendió
a decidir qué camino tomar
Hoy aprende a repetir:
ejecutar el mismo bloque de código
varias veces, sin escribirlo varias veces
Hoy vamos a ver
  • Un repaso rápido de los if
  • El ciclo for
  • El ciclo while
  • El ciclo do while
  • Cuándo usar cada uno
Antes de empezar
Lo que traemos de la clase pasada
if ejecuta un bloque solo si la condición es true
else cubre el camino cuando es false
else if encadena más caminos, de arriba hacia abajo
int nota = 85;

if (nota >= 90)
{
    Console.WriteLine("Excelente");
}
else if (nota >= 60)
{
    Console.WriteLine("Aprobado");
}
else
{
    Console.WriteLine("Reprobado");
}
Y cada condición se arma con los operadores
relacionales (== != > < >= <=)
y los lógicos (&& || !)
Un if hace la pregunta una sola vez
y sigue con el resto del programa
Un ciclo hace la misma clase de pregunta,
pero una y otra vez, mientras la respuesta sea true
El problema
Queremos mostrar "Hola" cinco veces 
Console.WriteLine("Hola");
Console.WriteLine("Hola");
Console.WriteLine("Hola");
Console.WriteLine("Hola");
Console.WriteLine("Hola");
Funciona. Pero, ¿y si fueran mil?
¿O si la cantidad la decide el usuario?
Para eso existen los ciclos
(también se les llama bucles o loops)
El ciclo for
Cada vez que el bloque se ejecuta
se le llama una iteración o una vuelta
El for se usa cuando ya sabemos
cuántas veces queremos repetir algo 
for (inicio; condición; actualización)
{
    // código que se repite
}
Entre los paréntesis van tres partes,
separadas por punto y coma 
for (int i = 0; i < 5; i++)
{
    Console.WriteLine("Hola");
}
int i = 0 inicio: se ejecuta una sola vez, al comenzar
i < 5 condición: se revisa antes de cada vuelta
i++ actualización: se ejecuta al final de cada vuelta
Una variable nueva: el contador
i es una variable que cuenta las vueltas.
Se usa i por costumbre, pero puede llamarse como quieran
Un operador nuevo
i++ significa lo mismo que i = i + 1:
le suma uno a la variable
i++ suma 1
i-- resta 1
i += 2 suma 2 (y con cualquier otro número igual)
Sigamos el for paso a paso 
for (int i = 0; i < 3; i++)
{
    Console.WriteLine("Hola");
}
Vuelta 1: i vale 0 · 0 < 3 es true · imprime "Hola" · i pasa a 1
Vuelta 2: i vale 1 · 1 < 3 es true · imprime "Hola" · i pasa a 2
Vuelta 3: i vale 2 · 2 < 3 es true · imprime "Hola" · i pasa a 3
Con i = 3, la condición 3 < 3 da false:
el ciclo termina y el programa sigue con la línea de abajo
El contador también se puede usar adentro 
for (int i = 0; i < 5; i++)
{
    Console.WriteLine("Vuelta número " + i);
}
Esto imprime 0, 1, 2, 3, 4.
Cuenta desde cero, igual que la mayoría de cosas en programación 
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("Vuelta número " + i);
}
Cambiando el inicio y la condición, ahora cuenta 1, 2, 3, 4, 5.
Las dos formas dan 5 vueltas
Ojo con el < y el <=
Un error muy común es pasarse o quedarse corto
una vuelta. Siempre revisen el primer y el último valor
Variaciones del for
Contar hacia atrás 
for (int i = 10; i >= 1; i--)
{
    Console.WriteLine(i);
}

Console.WriteLine("¡Despegue!");
Empieza en 10, la condición ahora es >=
y la actualización es i-- en vez de i++
Saltar de a más de uno 
for (int i = 2; i <= 20; i += 2)
{
    Console.WriteLine(i);
}
Imprime 2, 4, 6, 8 ... 20.
La actualización puede ser cualquier cambio sobre la variable
Que el usuario decida cuántas veces 
Console.WriteLine("¿Cuántas veces quieres repetir?");
int veces = int.Parse(Console.ReadLine());

for (int i = 0; i < veces; i++)
{
    Console.WriteLine("Hola");
}
Acumular un resultado 
int suma = 0;

for (int i = 1; i <= 10; i++)
{
    suma += i;
}

Console.WriteLine("La suma del 1 al 10 es " + suma);
La variable suma se declara afuera del for.
Si se declarara adentro, se reiniciaría en cada vuelta
Una tabla de multiplicar 
Console.WriteLine("¿Qué tabla quieres ver?");
int numero = int.Parse(Console.ReadLine());

for (int i = 1; i <= 10; i++)
{
    Console.WriteLine(numero + " x " + i + " = " + numero * i);
}
Un for con un if adentro 
for (int i = 1; i <= 20; i++)
{
    if (i % 2 == 0)
    {
        Console.WriteLine(i + " es par");
    }
}
Dentro de un ciclo puede ir cualquier código que ya conozcan:
variables, operaciones, consola, y también if
Resumen del for
Se usa cuando sabemos cuántas veces repetir
Junta inicio, condición y actualización en una sola línea
El contador puede subir, bajar o saltar de a más de uno
Descanso
10 minutos
El ciclo while
A veces no sabemos cuántas vueltas van a hacer falta
Pedir una clave hasta que sea correcta
Jugar mientras queden vidas
Sumar números hasta que el usuario escriba 0
Para eso sirve el while:
repite el bloque mientras la condición sea true 
while (condición)
{
    // código que se repite
}
El while solo tiene la condición.
El inicio y la actualización los tenemos que escribir nosotros, por separado
El mismo "Hola" cinco veces, ahora con while 
int i = 0;

while (i < 5)
{
    Console.WriteLine("Hola");
    i++;
}
int i = 0; el inicio, antes del while
i < 5 la condición, entre paréntesis
i++; la actualización, adentro del bloque
Es exactamente lo mismo que el for,
pero con las tres partes separadas
Peligro: el ciclo infinito 
int i = 0;

while (i < 5)
{
    Console.WriteLine("Hola");
}
Nadie le suma uno a i, así que la condición
nunca deja de ser true y el programa no termina
Si les pasa, detengan el programa con el botón de detener
de Visual Studio, o cierren la ventana de la consola
Otra diferencia importante
El while revisa la condición antes de empezar,
así que puede ejecutarse cero veces 
int vidas = 0;

while (vidas > 0)
{
    Console.WriteLine("Sigues jugando");
    vidas--;
}

Console.WriteLine("Game Over");
Como vidas arranca en 0, la condición da false
desde el principio y el bloque nunca se ejecuta
Ahora sí, un caso donde el while es lo ideal 
string clave = "";

while (clave != "hipermedia")
{
    Console.WriteLine("Escribe la clave:");
    clave = Console.ReadLine();
}

Console.WriteLine("Acceso concedido");
No sabemos cuántos intentos va a necesitar el usuario:
uno, diez, o ninguno si acierta de una
Ojo: clave empieza vacía a propósito,
para que la condición dé true y el while entre la primera vez
Sumar hasta que escriban 0 
int suma = 0;

Console.WriteLine("Escribe un número (0 para terminar):");
int numero = int.Parse(Console.ReadLine());

while (numero != 0)
{
    suma += numero;
    Console.WriteLine("Escribe otro número (0 para terminar):");
    numero = int.Parse(Console.ReadLine());
}

Console.WriteLine("La suma es " + suma);
Fíjense que tuvimos que pedir el número dos veces:
una antes del while y otra adentro
Resumen del while
Se usa cuando no sabemos cuántas veces repetir
Revisa la condición antes, puede no ejecutarse nunca
Hay que actualizar algo adentro, o se vuelve infinito
Descanso
10 minutos
El ciclo do while
En el ejemplo anterior tuvimos que repetir una línea:
pedir el número antes del while y otra vez adentro
El do while resuelve justo eso:
ejecuta el bloque primero y revisa la condición después 
do
{
    // código que se repite
}
while (condición);
Ojo con el punto y coma al final:
en el do while sí va, y es de los errores más comunes
La gran diferencia: el do while siempre se ejecuta
al menos una vez, aunque la condición sea false desde el inicio 
int vidas = 0;

do
{
    Console.WriteLine("Sigues jugando");
    vidas--;
}
while (vidas > 0);
Con vidas = 0, el while de antes no hacía nada.
Este do while imprime una vez y recién ahí revisa
Su lugar ideal: validar lo que escribe el usuario 
int edad;

do
{
    Console.WriteLine("Escribe tu edad (entre 1 y 120):");
    edad = int.Parse(Console.ReadLine());
}
while (edad < 1 || edad > 120);

Console.WriteLine("Tu edad es " + edad);
Hay que pedir el dato al menos una vez,
y repetirlo solo si lo que escribieron no sirve.
Y edad se declara antes del do, para poder usarla en el while
Otro clásico: un menú 
int opcion;

do
{
    Console.WriteLine("1. Jugar");
    Console.WriteLine("2. Ver puntajes");
    Console.WriteLine("0. Salir");
    opcion = int.Parse(Console.ReadLine());

    if (opcion == 1)
    {
        Console.WriteLine("Empieza el juego");
    }
    else if (opcion == 2)
    {
        Console.WriteLine("Estos son los puntajes");
    }
}
while (opcion != 0);
El menú se muestra siempre una vez y se repite
hasta que escriban 0. Aquí el do while cae perfecto
Resumen del do while
Es un while con la condición al final
Se ejecuta mínimo una vez, siempre
Termina con punto y coma después del while
¿Cuál uso?
for · sé exactamente cuántas veces repetir
while · repito mientras algo pase, y quizás ni una vez
do while · repito mientras algo pase, pero mínimo una vez
Algunos escenarios
Imprimir del 1 al 100 → for
Una cuenta regresiva → for
Pedir la clave hasta que acierte → while
Jugar mientras queden vidas → while
Algunos escenarios
Mostrar un menú y repetirlo → do while
Validar que una edad sea razonable → do while
Sumar números hasta que escriban 0 → while o do while
La verdad es que cualquiera de los tres puede hacer
el trabajo de los otros. La idea es elegir
el que deje el código más claro y más corto
Errores típicos con ciclos
Ciclo infinito: olvidar actualizar la variable de la condición
Una vuelta de más o de menos: confundir < con <=
Punto y coma de más: un for (...); vacía el ciclo
Revisión
¿Qué vimos hoy?
Vimos que un ciclo repite un bloque de código
mientras una condición sea true
El for cuando sabemos cuántas veces,
el while cuando no sabemos y puede no ejecutarse,
y el do while cuando debe ejecutarse al menos una vez
