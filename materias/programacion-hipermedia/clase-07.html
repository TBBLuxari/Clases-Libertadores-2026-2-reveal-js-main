El if
¿Qué es una condición?
Una condición es una pregunta que el código se hace,
y la respuesta siempre es true o false 
int edad = 20;
bool esMayor = edad >= 18;   // true
Recordemos los operadores relacionales
== igual · != distinto
> mayor · < menor
>= mayor o igual · <= menor o igual
Cualquier expresión con un operador relacional
ya es, por sí sola, una condición
La palabra if
if es una palabra reservada, seguida
de una condición entre paréntesis 
if (condición)
{
    // código que se ejecuta si la condición es true
}
Si la condición es true, el código
dentro de las llaves { } se ejecuta
Si es false, ese bloque completo
simplemente se salta, como si no existiera 
int edad = 20;

if (edad >= 18)
{
    Console.WriteLine("Es mayor de edad");
}
Ojo con las llaves
Siempre usen { }, aunque sea
una sola línea de código adentro
Sin llaves, C# solo asocia el if
con la línea inmediatamente siguiente,
y es una fuente muy común de errores 
Console.WriteLine("¿Cuántos años tienes?");
int edad = int.Parse(Console.ReadLine());

if (edad >= 18)
{
    Console.WriteLine("Ya puedes votar");
}

Console.WriteLine("Gracias por participar");
La última línea se imprime siempre,
se cumpla o no la condición del if

El else
El if solo cubre un camino:
qué hacer cuando la condición es true
Pero casi siempre también nos importa
qué hacer cuando es false 
if (condición)
{
    // se ejecuta si la condición es true
}
else
{
    // se ejecuta si la condición es false
}
else no lleva condición propia:
significa "en cualquier otro caso" 
Console.WriteLine("¿Cuántos años tienes?");
int edad = int.Parse(Console.ReadLine());

if (edad >= 18)
{
    Console.WriteLine("Ya puedes votar");
}
else
{
    Console.WriteLine("Todavía no puedes votar");
}
De los dos bloques, siempre se ejecuta exactamente uno,
nunca los dos, y nunca ninguno

El else if
A veces no basta con dos caminos,
hacen falta tres, cuatro, o más
Para eso encadenamos condiciones
con else if 
if (condición1)
{
    // se ejecuta si condición1 es true
}
else if (condición2)
{
    // se ejecuta si condición1 es false y condición2 es true
}
else
{
    // se ejecuta si ninguna de las anteriores fue true
}
C# evalúa las condiciones de arriba hacia abajo,
y se detiene apenas encuentra la primera que sea true
El else final es opcional:
se puede encadenar solo con if y else if
Por eso el orden importa
Si escriben las condiciones en el orden equivocado,
una puede "tapar" a las demás y nunca dejarlas evaluarse 
int nota = 95;

if (nota >= 60)
{
    Console.WriteLine("Aprobado");
}
else if (nota >= 90)
{
    Console.WriteLine("Excelente");   // nunca se imprime esto
}
Con nota = 95, la primera condición
ya dio true, así que ahí se detiene:
"Excelente" nunca se alcanza a evaluar
La forma correcta
Cuando trabajan con rangos, siempre
van del caso más específico al más general 
int nota = 95;

if (nota >= 90)
{
    Console.WriteLine("Excelente");
}
else if (nota >= 60)
{
    Console.WriteLine("Aprobado");
}
else
{
    Console.WriteLine("Reprobado");
}
Ahora sí: nota = 95 cae en "Excelente",
y cualquier cosa por debajo de 60 cae en el else final

Operadores lógicos
A veces una condición sola no alcanza:
necesitamos combinar varias en una sola pregunta
&& Y lógico: las dos condiciones deben ser true
|| O lógico: basta con que una sea true
! Negación: invierte true por false
int edad = 30;
bool tieneCarnet = true;

bool puedeConducir = edad >= 18 && tieneCarnet;
Con &&, si cualquiera de las dos
condiciones da false, todo el resultado ya es false 
int edad = 15;

bool puedeVerFilm = edad >= 18 || edad >= 13;   // true, con acompañante
Con ||, basta con que una sola
de las condiciones sea true 
int edad = 20;

if (edad >= 18 && edad <= 65)
{
    Console.WriteLine("Está en el rango");
}
&& y || son perfectos para
expresar rangos en una sola condición,
sin necesitar else if
