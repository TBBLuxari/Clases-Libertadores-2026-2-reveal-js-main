Diagramas de flujo,
desde cero
Recordemos: todo algoritmo tiene
entrada, proceso y salida
Entrada: lo que necesita para empezar
Proceso: los pasos que lo transforman
Salida: el resultado final
Un diagrama de flujo es
esa misma lógica, pero dibujada
con símbolos estándar y flechas
¿Por qué dibujarlo?
Se entiende de un vistazo, sin leer todo el texto
Es más fácil detectar pasos que faltan o sobran
Es un estándar universal: cualquier programador lo reconoce
Los símbolos, uno por uno
óvalo
Marca dónde empieza
y dónde termina el diagrama.
Siempre hay un solo óvalo de inicio, y al menos uno de fin
paralelogramo
Representa una entrada
(LEER) o una salida (ESCRIBIR) de datos
rectángulo
Representa un paso,
una acción o un cálculo
rombo
Representa una decisión:
una pregunta que se responde Sí o No.
Siempre salen dos caminos
flecha
Indica el orden: hacia dónde sigue el flujo.
Le da el nombre: FLUJO
Los cuatro símbolos, juntos
Al tablero

Cada uno dibuja los 4 símbolos
en su cuaderno, con su nombre debajo
2-3 minutos. Caminar verificando que dibujen óvalo, paralelogramo, rectángulo y rombo correctamente (no cuadrados en vez de rectángulos, no círculos en vez de óvalos).
Primer diagrama: sin decisiones
Al tablero

Algoritmo: calcular cuánto
pagar por unas empanadas 
INICIO
  LEER cantidad de empanadas
  LEER precio de una empanada
  MULTIPLICAR cantidad por precio
  ESCRIBIR el total a pagar
FIN
Reglas para dibujar bien
Un solo óvalo de inicio, al menos uno de fin
Las flechas nunca quedan sueltas, todo se conecta
Un rectángulo = un paso, no varios amontonados
El flujo va, casi siempre, de arriba hacia abajo
Segundo diagrama: con decisión
Al tablero

Algoritmo: decir si un número
es par o impar 
INICIO
  LEER un número
  SI el número es par ENTONCES
    ESCRIBIR "es par"
  SINO
    ESCRIBIR "es impar"
FIN
Todavía no vamos a programar esto en C#,
eso llega más adelante en el curso.
Hoy solo aprendemos a dibujarlo
Fíjense: los dos caminos (Sí y No)
se vuelven a juntar antes de un único FIN

Operadores
Con las variables ya declaradas,
ahora vamos a hacer cosas con ellas
Operadores aritméticos
+ suma
- resta
* multiplicación
/ división
% módulo (el residuo de una división)
int a = 10;
int b = 3;
int suma = a + b;     // 13
int resto = a % b;    // 1
Ejemplo de la vida real
El módulo % sirve para saber, por ejemplo,
si un número es par (residuo 0 al dividir por 2)
Operadores de comparación
== ¿son iguales?
!= ¿son diferentes?
< menor que
> mayor que
<= menor o igual
>= mayor o igual
Ojo: un solo = es asignar un valor
doble == es comparar
Si vienen de JavaScript algún día,
en C# no existe el triple ===,
solo el doble == 
int edad = 20;
bool esMayorDeEdad = edad >= 18;   // true
Expresiones
Una expresión es combinar variables
y operadores en una sola línea 
int total = (precio * cantidad) - descuento;
El resultado de una expresión
se puede guardar en otra variable,
o usar directamente en un Console.WriteLine
Conversión de tipos
A veces necesitamos que un dato
cambie de tipo
Conversión implícita
C# la hace solo, cuando no hay riesgo
de perder información 
int edad = 20;
double edadDecimal = edad;   // de int a double, sin problema
Conversión explícita
Hay que forzarla nosotros, porque
se puede perder información 
double promedio = 4.8;
int promedioEntero = (int)promedio;   // 4, se pierde el decimal
Texto ↔ número
Para eso no sirve el cast con paréntesis,
se usan funciones especiales 
string textoEdad = "20";
int edad = int.Parse(textoEdad);       // texto a número

int edad2 = 20;
string textoEdad2 = edad2.ToString();  // número a texto
Estas conversiones las vamos
a practicar mucho en un rato
A predecir
Sin correr el código todavía

¿Qué valor queda en cada variable?
10 minutos. En parejas, escriben en papel qué creen que da cada expresión, antes de correrlo en Visual Studio para comprobar. 
int x = 7;
int y = 2;
int resultado1 = x % y;
bool resultado2 = x > y * 4;
double resultado3 = (double)x / y;
Recibir datos
por consola
¿Se acuerdan del LEER del diagrama?
Así se hace en C# de verdad 
string nombre = Console.ReadLine();
Console.ReadLine() siempre devuelve
texto (string), sin importar qué escriba el usuario
Si necesitamos un número,
hay que convertirlo nosotros 
Console.WriteLine("¿Cuántos años tienes?");
string textoEdad = Console.ReadLine();
int edad = int.Parse(textoEdad);
Si el usuario escribe algo
que no es un número ahí,
el programa se rompe (error de conversión)
Al tablero

Ejemplo completo: leer nombre y edad,
y calcular en qué año cumple 100 años
Escribir el programa en vivo en Visual Studio, proyectando pantalla. Ejecutar y probar con datos reales de algún estudiante que se ofrezca. 
Console.WriteLine("¿Cómo te llamas?");
string nombre = Console.ReadLine();

Console.WriteLine("¿Cuántos años tienes?");
int edad = int.Parse(Console.ReadLine());

int anioActual = 2026;
int anioCien = anioActual + (100 - edad);

Console.WriteLine(nombre + ", vas a cumplir 100 años en " + anioCien);
