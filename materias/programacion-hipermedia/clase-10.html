Algoritmo

Una secuencia de pasos, ordenados y precisos,
para resolver un problema o cumplir una tarea
Entrada
lo que necesita para empezar
Proceso
los pasos que lo transforman
Salida
el resultado final
Un buen algoritmo es finito preciso ordenado y siempre termina en un resultado

Pseudocódigo

INICIO
  1. LEER edad
  2. SI edad >= 18
       ESCRIBIR "Mayor de edad"
     SINO
       ESCRIBIR "Menor de edad"
FIN
Un paso = una acción clara
Verbos: LEER, ESCRIBIR, CALCULAR
Sin { } ni ;: se escribe para personas, no para el computador

Del pseudocódigo al diagrama

INICIO FIN   óvalo: dónde empieza y dónde termina
LEER ESCRIBIR   paralelogramo: entra o sale un dato
CALCULAR GUARDAR   rectángulo: un paso, un proceso
SI … SINO   rombo: una pregunta con dos caminos (Sí / No)
orden   flecha: hacia dónde sigue el flujo, nunca queda suelta

if, else, else if

if

El bloque se ejecuta solo si la condición es true. Si no, se salta.

if (condición)
{
    // ...
}

if / else

Entra uno de los dos. Nunca los dos, nunca ninguno.

if (condición)
{
    // true
}
else
{
    // false
}

else if

Varios caminos. Gana la primera que sea true. El orden importa.

if (cond1)
{
}
else if (cond2)
{
}
else
{
}

while y do while

while

Revisa antes: puede ejecutarse 0 veces

int vidas = 3;

{
    Console.WriteLine("Juega");
    vidas--;
}

do while

Revisa después: mínimo 1 vez y termina con ;

do
{
    opcion = int.Parse(Console.ReadLine());
}
while (opcion != 0);
 Si adentro no cambia nada de la condición, el ciclo no termina nunca

¿Cuál ciclo uso?

Todo se puede combinar

if dentro de ciclo

El ciclo da las vueltas, el if decide en cada una

for (int i = 1; i <= 5; i++)
{
    if (i == 3)
    {
        Console.WriteLine("¡Tres!");
    }
}

ciclo dentro de if

El if decide si el ciclo se ejecuta

if (n > 0)
{
    for (int i = 1; i <= n; i++)
    {
        Console.WriteLine(i);
    }
}

ciclo dentro de ciclo

Por cada vuelta del de afuera, el de adentro da todas las suyas

for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        Console.WriteLine(i + " x " + j);
    }
}

Los errores de siempre

= o ==

if (edad = 18)

Un = asigna. Para comparar van dos ==

Punto y coma de más

for (...);

Con el ; el ciclo queda vacío y el bloque corre una sola vez

< o <=

i < 5   o   i <= 5

Una vuelta de más o de menos

Ciclo infinito

while (i < 5)

Nadie le suma 1 a i y la condición nunca cambia

Variable adentro

int suma = 0;

Si va dentro del ciclo, vuelve a 0 en cada vuelta

Orden del else if

nota >= 60 antes de nota >= 90

La primera que da true tapa a las demás

El paquete y su tarifa

Calentamientoen papel 10 min

Una empresa de envíos cobra según el peso en kilos del paquete. Este es el pseudocódigo de su programa. Dibujen el diagrama de flujo equivalente.

INICIO
  LEER peso
  SI peso <= 1
    tarifa = 5000
  SINO
    SI peso <= 5
      tarifa = 12000
    SINO
      tarifa = 20000
  ESCRIBIR tarifa
FIN

Puntos de control

  1. Empieza y termina con óvalos y todo está conectado con flechas
  2. LEER y ESCRIBIR van en paralelogramos
  3. Hay dos rombos, uno por cada SI, con las salidas rotuladas Sí y No
  4. Cada tarifa va en un rectángulo, en la rama que le corresponde
  5. Todas las ramas se juntan en un solo ESCRIBIR antes del FIN
Cuando terminen: escriban ese mismo programa en C# y pruébenlo con 1, 3 y 8 kilos.
Papel. Error típico: un solo rombo con tres salidas, o poner el segundo rombo en la rama del Sí en vez de en la del No. El segundo SI está dentro del SINO del primero. Revisar que las flechas de cada rombo estén rotuladas y que las tres ramas converjan en el ESCRIBIR.

La cafetería con descuento

Intermediodiagrama a código 12 min

Este es el diagrama de flujo del programa de una cafetería, que da 10% de descuento a los estudiantes en compras grandes. Escríbanlo en C#.

Puntos de control

  1. Proyecto de consola que compila y lee las dos entradas como enteros
  2. La condición del rombo queda escrita en un solo if
  3. El camino del Sí calcula el total con el 10% de descuento
  4. El camino del No deja el total igual a la compra
  5. Muestra el total una sola vez, al final, y funciona con 30000 (estudiante), 20000 (estudiante) y 50000 (no estudiante)
Diagrama a código. La condición compuesta (esEstudiante == 1 y compra mayor a 20000) debe quedar en un solo if con &&. El 10% en enteros: total = compra - compra / 10. Caso límite: con exactamente 20000 no hay descuento (la condición es mayor que, no mayor o igual).

El mensaje de la nota

Intermedioen papel 12 min

Alguien escribió este programa y nadie lo entiende. Pásenlo a pseudocódigo y luego dibujen su diagrama de flujo.

int nota = int.Parse(Console.ReadLine());

if (nota < 0 || nota > 100)
{
    Console.WriteLine("Nota inválida");
}
else if (nota >= 90)
{
    Console.WriteLine("Excelente");
}
else if (nota >= 60)
{
    Console.WriteLine("Aprobado");
}
else
{
    Console.WriteLine("Reprobado");
}

Puntos de control

  1. Identifican qué dato entra y qué mensajes pueden salir
  2. Escriben el pseudocódigo con INICIO, FIN, LEER y ESCRIBIR
  3. Las decisiones quedan en el mismo orden que en el código (SI, SINO SI, SINO)
  4. Dibujan el diagrama con óvalos, paralelogramos y un rombo por cada condición
  5. Siguiendo su diagrama, dicen qué imprime el programa con 95, 70, 30 y 150
Código a pseudocódigo y diagrama. Son tres rombos en cascada: la salida No de cada uno lleva al siguiente, y las cuatro ramas terminan en un ESCRIBIR que va al FIN. Respuestas del punto 5: 95 Excelente, 70 Aprobado, 30 Reprobado, 150 Nota inválida. Un buen extra: preguntar qué pasa con el 90 exacto y con el 60 exacto.

El recibo de la cafetería

Calentamiento 15 min

La cafetería de la universidad necesita un programa para cobrar almuerzos. Pide el nombre del cliente, cuántos almuerzos lleva y el precio de cada uno.

Con 10 o más almuerzos hay 10% de descuento, y con 20 o más, 20%. Al valor ya con descuento se le suma el IVA del 19%. Al final se imprime el recibo.

Si escriben: Ana · 12 · 9000--- RECIBO ---
Cliente: Ana
Subtotal: 108000
Descuento: 10800
IVA: 18468
Total: 115668

Puntos de control

  1. Lee el nombre, la cantidad y el precio (los números como int)
  2. Calcula y muestra el subtotal
  3. Aplica el descuento correcto: ninguno, 10% o 20% (prueben con 9, 10, 19 y 20)
  4. Calcula el IVA sobre el valor con descuento y muestra el total
  5. Si el total pasa de 200000, agrega la línea "Envío gratis"
12-15 minutos. Repasa variables, conversión con int.Parse, operadores aritméticos y else if. Fallos típicos: comparar primero con 10 y tapar el caso de 20 (el orden del else if), o calcular el IVA sobre el subtotal en vez de sobre el valor con descuento. Todo en enteros a propósito (la coma decimal del teclado en español complica el double.Parse).

La montaña rusa

Intermedio 15 min

Para subir a la montaña rusa hay que tener mínimo 8 años y medir mínimo 120 cm. Los menores de 12, además, solo suben si vienen con un adulto, y eso se pregunta únicamente cuando hace falta. A quienes tienen 65 años o más se les deja subir, pero con un aviso de precaución.

El programa pide la edad y la estatura, y dice si la persona puede subir o por qué no.

Edad 5 · Estatura 90No puede subir: no cumple la edad ni la estatura
Edad 70 · Estatura 160Puede subir
Aviso: se recomienda precaución

Puntos de control

  1. Lee la edad y la estatura como enteros
  2. Deja subir a quien cumple edad y estatura, y rechaza a quien no cumple alguna
  3. Al rechazar, dice el motivo exacto: la edad, la estatura o las dos
  4. A los menores de 12 que cumplen todo les pregunta si vienen con un adulto, y a los demás no
  5. A los de 65 o más que sí pueden subir les muestra el aviso (prueben con 7, 8, 11, 12, 64 y 65)
12-15 minutos. Repasa if / else if / else, &&, || y if anidados. Cuidado con el aviso de los de 65 o más: solo si de verdad pueden subir (un señor de 70 años que mide 100 cm no debe ver el aviso). Los mensajes exactos no importan, importa la lógica.

La tabla con estadísticas

Intermedio 15 min

Un profesor de matemáticas quiere una tabla de multiplicar con estadísticas. El programa pide un número y hasta qué fila mostrar (por ejemplo, el 7 hasta la fila 10). Cada resultado par se marca con un asterisco.

Al final dice cuántos resultados fueron pares, cuántos fueron múltiplos de 5 y cuánto da la suma de todos los resultados.

Número 7 · Hasta la fila 107 x 1 = 7
7 x 2 = 14 *
7 x 3 = 21
...
7 x 10 = 70 *
Pares: 5
Múltiplos de 5: 2
Suma de resultados: 385

Puntos de control

  1. Lee el número y las filas, y muestra cada fila con el formato "7 x 1 = 7"
  2. Marca con * solo los resultados pares
  3. Cuenta cuántos resultados fueron pares y lo muestra al final
  4. Suma todos los resultados y muestra el total
  5. Cuenta los múltiplos de 5 (un resultado puede ser par y múltiplo de 5 a la vez) y prueba con 12 y 5 filas
12-15 minutos. Repasa for, if dentro de for, contador y acumulador. Errores típicos: declarar los contadores dentro del for (se reinician), usar else if entre "par" y "múltiplo de 5" (el 70 es las dos cosas, así que van en ifs separados) y pasarse o quedarse corto una fila (< contra <=).

El cajero automático

Reto 25 min

Un cajero arranca con un saldo de 500000 y el PIN correcto es 1234. El usuario tiene 3 intentos para escribirlo; si falla los 3, la tarjeta se bloquea y el programa termina.

Si entra, ve un menú que se repite hasta que escoja salir: consultar saldo, retirar, depositar o salir. Los retiros no pueden superar el saldo y deben ser múltiplos de 10000. Los depósitos deben ser mayores que cero.

EjemploEscribe tu PIN:
0000
PIN incorrecto. Intentos restantes: 2
Escribe tu PIN:
1234
1. Consultar saldo
2. Retirar
3. Depositar
0. Salir

Puntos de control

  1. Pide el PIN y deja entrar solo con 1234
  2. Da 3 intentos, avisa cuántos quedan y, al fallar el tercero, dice "Tarjeta bloqueada" sin mostrar el menú
  3. El menú se repite hasta que escojan 0; con 1 muestra el saldo y una opción inválida avisa
  4. Retirar descuenta del saldo, pero rechaza montos mayores al saldo o que no sean múltiplos de 10000
  5. Depositar suma solo montos positivos; al salir se despide con el saldo final y cuántos movimientos exitosos hubo
20-25 minutos, es el ejercicio más largo. Repasa while (intentos), do while (menú), else if, && y ||, banderas (bool). Dónde se traban: (1) mezclar el while del PIN con el do while del menú: son dos ciclos separados, el primero antes del segundo; (2) mostrar "Intentos restantes: 0" en el tercer fallo; (3) permitir retiros negativos o de 0; (4) olvidar contar solo los movimientos exitosos. Está bien que muchos lleguen al punto 3 o 4: para eso son los puntos de control.

La sala de cine

Reto 20 min

El programa pide cuántas filas y cuántas columnas tiene una sala (no acepta 0 ni negativos) y dibuja el mapa: un asiento ocupado es una X y uno libre es una L.

Están ocupados los asientos donde fila + columna da un número par (contando desde 1). Al final muestra cuántos están ocupados, cuántos libres y el porcentaje de ocupación como número entero.

3 filas · 5 columnasFila 1: X L X L X
Fila 2: L X L X L
Fila 3: X L X L X
Ocupados: 8 | Libres: 7
Ocupación: 53%

Puntos de control

  1. Pide las filas y las columnas, y no sigue hasta que ambas sean mayores que 0
  2. Muestra una línea por cada fila: "Fila 1:", "Fila 2:"...
  3. En cada fila dibuja todos los asientos de la sala (por ahora todos L)
  4. Marca con X los asientos ocupados según la regla
  5. Cuenta ocupados y libres, y muestra el porcentaje de ocupación como número entero
15-20 minutos. Repasa for dentro de for, do while para validar, if con %, y contadores. Como todavía no se vio Console.Write, cada fila se arma en un string que se va ampliando con + y se imprime al terminar las columnas; si alguien no lo ve, darle esa pista y nada más. Error típico: declarar el string de la fila fuera del for externo (la fila 2 arrastra la fila 1).

El resumen de notas

Reto 25 min

Una profesora quiere el resumen de las notas de su curso. El programa pregunta cuántos estudiantes hay (al menos 1) y luego pide la nota de cada uno, un entero entre 0 y 100. Si la nota no es válida, se la vuelve a pedir al mismo estudiante.

Al final muestra el promedio con decimales, la mejor y la peor nota, y cuántos aprobaron (60 o más) y cuántos reprobaron.

4 estudiantes · 80, 55, 100, 62Promedio: 74,25
Mejor nota: 100
Peor nota: 55
Aprobaron: 3
Reprobaron: 1

Puntos de control

  1. Pregunta cuántos estudiantes hay y vuelve a preguntar si es menor que 1
  2. Pide exactamente esa cantidad de notas, indicando de qué estudiante es cada una
  3. Rechaza las notas fuera de 0 a 100 y la vuelve a pedir sin contar un estudiante de más
  4. Calcula el promedio con decimales (ojo con la división entre enteros)
  5. Muestra mejor nota, peor nota, aprobados y reprobados (prueben también con un solo estudiante)
20-25 minutos. Integra todo: do while (dos validaciones), for, acumulador, mayor y menor, contador, cast a double. El promedio sale con coma o con punto según la configuración regional del computador. Error típico del punto 4: (suma / cantidad) con enteros y luego convertir a double, que ya perdió los decimales; hay que convertir antes de dividir.

Adivina el número

Intermedio 15 min

El programa piensa en el 37 (fijo). El usuario tiene 7 intentos para adivinarlo. Después de cada intento errado dice "Muy alto" o "Muy bajo", y si estuvo a menos de 5 de distancia, además grita "¡Caliente!".

Si acierta, lo felicita y dice en cuántos intentos; si se acaban, revela el número.

Puntos de control

  1. Pide un número y dice si acertó
  2. Repite hasta que acierte, con la pista de alto o bajo
  3. Cuenta los intentos y, al acertar, dice en cuántos lo logró
  4. A los 7 intentos se acaba: pierde y se revela el número
  5. Agrega "¡Caliente!" cuando estuvo a menos de 5 de distancia sin acertar
La distancia sin Math.Abs: restar y, si da negativo, cambiarle el signo.
