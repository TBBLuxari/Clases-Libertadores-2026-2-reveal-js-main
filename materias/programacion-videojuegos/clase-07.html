¿Qué es Unity?
Phaser era una librería: JavaScript puro,
corriendo dentro de una página web
Unity es un motor de videojuegos completo:
un programa aparte, con su propio editor visual
Es uno de los motores más usados de la industria:
sirve igual para juegos 2D y 3D, móvil, PC o consola
El lenguaje también cambia: en Unity se programa en C#,
no en JavaScript
Buenas noticias
Las ideas de fondo son las mismas que ya saben:
variables, if, for, funciones. Solo cambia un poco la sintaxis
Con lo que ya saben de JS, ¿qué esperan que
sea distinto en C#?

C# es más estricto: hay que decir de qué tipo es cada variable, y todo va organizado dentro de clases.
Hoy no vamos a explicar C# desde cero como si fuera
la primera vez que programan. Vamos directo a lo que Unity necesita

GameObjects y Components
En Unity, todo lo que existe en una escena
(personaje, piso, cámara, luz) es un GameObject
Un GameObject vacío no hace absolutamente nada:
no se ve, no choca, no se mueve solo
Gana comportamiento cuando le agregan Components:
piezas que se enchufan una encima de otra
Un componente que todo GameObject trae de fábrica,
y que no se puede quitar: el Transform
El Transform guarda position, rotation y scale:
dónde está, hacia dónde mira, y qué tan grande es
Al tablero · crear un GameObject 3D
Mostrando: Inspector
Click derecho en Hierarchy → 3D Object → Cube
Miren el Inspector: el cubo ya trae Transform,
Mesh Renderer (cómo se dibuja) y Box Collider (con qué choca)
Eso es exactamente el concepto: un GameObject
+ varios Components combinados = el cubo que ven
GameObjects 2D vs 3D
3D Object: Cube, Sphere, Capsule, Plane, Cylinder:
primitivas con volumen real, pensadas para un mundo en 3 dimensiones
2D Object → Sprite: una imagen plana.
Es el mismo concepto que usaban en Phaser, pero ahora dentro de Unity
Hoy trabajamos en 3D,
pero el mismo GameObject + Components aplica igual para un juego 2D

Scripting en C#
Hasta ahora todo lo hicimos a mano, con el mouse.
Para que algo reaccione al jugador, necesitamos código
Al tablero · crear un script
En Project: click derecho → Create → C# Script,
lo llamamos MovimientoCubo
Ojo con esto
El nombre del archivo y el nombre de la clase deben coincidir:
si no, Unity marca error 
using UnityEngine;

public class MovimientoCubo : MonoBehaviour
{
    void Start()
    {

    }

    void Update()
    {

    }
}
MonoBehaviour es la clase base de todo script
que se puede enganchar a un GameObject
Start() corre una sola vez, al iniciar el juego:
bueno para preparar cosas
Update() corre una vez por cuadro, muchas veces por segundo:
aquí va todo lo que necesita revisarse todo el tiempo (input, movimiento)
Si quieren imprimir un mensaje una sola vez al arrancar,
¿en cuál de los dos lo ponen?

En Start(). Update() lo repetiría en cada cuadro, cientos de veces por segundo.
Al tablero · engancharlo

Arrastren el script MovimientoCubo desde Project
hasta encima de su cubo en el Hierarchy
Ahora aparece como un Component más en el Inspector del cubo:
exactamente igual que el Mesh Renderer o el Box Collider
Variables públicas: el puente con el Inspector 
public class MovimientoCubo : MonoBehaviour
{
    public float velocidad = 5f;
}
public en Unity tiene un efecto extra:
esa variable aparece editable en el Inspector, sin tocar código
Por qué esto es tan útil
Pueden ajustar la velocidad mientras el juego corre,
probando valores, sin parar y volver a escribir código
Ejercicio (5 min): creen su script, engánchenlo al cubo,
agreguen una variable pública "velocidad" y cámbienla desde el Inspector
Moviendo el cubo
Para leer el teclado usamos Input.GetAxis 
float horizontal = Input.GetAxis("Horizontal"); // A/D o flechas
float vertical = Input.GetAxis("Vertical");     // W/S o flechas
Al tablero · mover con position
void Update()
{
    float horizontal = Input.GetAxis("Horizontal");
    float vertical = Input.GetAxis("Vertical");

    transform.position += new Vector3(horizontal, 0f, vertical) * velocidad * Time.deltaTime;
}
Empezamos con transform.position directo,
igual que hacían con personaje.x en Phaser: es la forma más simple y explícita
Vector3 guarda 3 números (X, Y, Z) juntos:
en 3D, todo movimiento y posición se maneja así
¿Por qué Time.deltaTime?
Update() no corre a una velocidad fija:
corre una vez por cada cuadro que la computadora logra dibujar
Si NO multiplican por Time.deltaTime, y dos computadores
corren su juego (uno a 30 cuadros por segundo, otro a 120),
¿qué pasa?

El de 120 movería el cubo 4 veces más rápido en el mismo segundo real: el juego se sentiría distinto según la máquina.
Time.deltaTime es el tiempo real, en segundos,
que pasó desde el cuadro anterior
Multiplicar por eso convierte "una cantidad por cuadro"
en "una cantidad por segundo", sin importar qué tan rápido corra la máquina
Otras formas de mover un objeto
Unity también tiene transform.Translate,
un atajo para mover con más contexto que sumar a position a mano 
transform.Translate(movimiento, Space.World); // igual que sumar a position
transform.Translate(movimiento, Space.Self);  // relativo a hacia dónde mira
Space.World mueve según los ejes fijos del mundo
(lo mismo que hicimos con position)
Space.Self mueve según los propios ejes del objeto:
si está rotado, "adelante" deja de ser +Z del mundo, y pasa a ser hacia donde el objeto mira
Ojo con esto
Si no ponen el segundo parámetro, Translate usa Space.Self por defecto
Hay una tercera opción: transform.forward,
un vector que siempre apunta hacia donde el objeto está mirando ahora mismo 
transform.position += transform.forward * velocidad * Time.deltaTime;
Esto se vuelve útil apenas el objeto puede rotar:
"avanzar" deja de ser siempre "ir hacia +Z" y pasa a ser "ir hacia donde estoy mirando"
Por qué hoy nos quedamos con position
Es la más simple de las tres, y la más parecida a lo que ya hacían en Phaser.
Translate y forward los van a necesitar apenas el movimiento dependa de la rotación

Rotando el cubo
Al tablero
if (Input.GetKey(KeyCode.Q))
    transform.Rotate(Vector3.up, -velocidadRotacion * Time.deltaTime);

if (Input.GetKey(KeyCode.E))
    transform.Rotate(Vector3.up, velocidadRotacion * Time.deltaTime);
transform.Rotate gira el objeto sobre un eje:
Vector3.up es el eje Y, o sea girar como un trompo visto desde arriba
No olviden declarar velocidadRotacion como variable pública,
igual que hicieron con velocidad
