¿Cómo funciona un videojuego?
A grandes rasgos, todo videojuego
está haciendo lo mismo una y otra vez,
muchísimas veces por segundo
Eso se llama
Game Loop
Literal, un bucle que nunca para
Es como el corazón del juego
si deja de latir, el juego se congela
El game loop hace 3 cosas, en orden
  1. Leer entradas (Input)
  2. Actualizar el estado (Update)
  3. Dibujar en pantalla (Render)
while (juegoActivo)
{
    LeerInput();
    Actualizar();
    Dibujar();
}
Input
¿El jugador movió el personaje?
¿Presionó saltar?
Update
Con esa información, se recalcula todo:
posiciones, físicas, colisiones, vida
Render
Se dibuja el resultado en pantalla
un fotograma más
Y eso se repite 60 veces por segundo
o más, sin que el jugador lo note
Cada una de esas repeticiones
es lo que conocemos como un frame
Unity ya trae este bucle construido
nosotros solo vamos a escribir
qué pasa dentro de cada paso
Pero eso todavía es solo la idea
para que funcione de verdad,
hay que escribirlo con código real
Así se ve el Update de Unity 
public class Jugador : MonoBehaviour
{
    public float velocidad = 5f;

    void Update()
    {
        float h = Input.GetAxis("Horizontal");
        transform.Translate(Vector3.right * h * velocidad * Time.deltaTime);
    }
}
Input.GetAxis lee el teclado o el control
Update() se ejecuta solo, cada frame
y el Render lo hace Unity por nosotros
Para escribir esa línea,
ya estamos usando matemáticas:
posición, dirección, velocidad, tiempo
¿Qué pasa si el juego corre
más rápido en un computador que en otro?
Por eso existe Time.deltaTime
el tiempo que pasó desde el último frame
Así el personaje se mueve igual de rápido
sin importar qué tan potente sea el computador
Y para que algo salte o caiga 
public class Salto : MonoBehaviour
{
    public Rigidbody2D rb;
    public float fuerzaSalto = 8f;

    void Update()
    {
        if (Input.GetButtonDown("Jump"))
            rb.velocity = new Vector2(rb.velocity.x, fuerzaSalto);
    }
}
Eso ya es física:
gravedad, velocidad, colisiones
el motor la resuelve, nosotros la usamos
Y por eso, antes de programar algo
hay que entender cómo funciona
en la vida real
