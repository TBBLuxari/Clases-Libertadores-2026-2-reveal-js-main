Colisiones, la versión rápida
Ahora mismo, si dos sprites se tocan en su juego,
no pasa nada — se atraviesan como fantasmas
Y tiene sentido: para Phaser, cada sprite
es solo una imagen flotando en el aire, sin relación con las demás
La clase pasada hubiéramos armado esto
a mano: comparar bordes (x, y, ancho, alto) de cada sprite
Hoy nos la saltamos
Esa cuenta a mano se llama colisión AABB —
es la base de cómo funciona todo motor de física
Pero existe una razón para no escribirla a mano:
con varios objetos, la cuenta crece muy rápido,
y hay casos raros (objetos rápidos, formas no rectangulares)
Por eso Phaser ya trae un motor de física
integrado que resuelve todo esto por ustedes: Arcade Physics
Arcade Physics
Al tablero — encenderlo en el config
const config = {
  type: Phaser.AUTO,
  width: 800,
  height: 600,
  physics: {
    default: "arcade",
    arcade: {
      gravity: { y: 0 },
      debug: false
    }
  },
  scene: { preload: preload, create: create, update: update }
};
gravity: { y: 0 }: por ahora nadie cae solo
debug: true dibuja las cajas de colisión, útil mientras prueban
Al tablero — sprites con física
function create() {
  personaje = this.physics.add.sprite(400, 300, "personaje");
}
En vez de this.add.sprite, usamos this.physics.add.sprite
Un sprite físico tiene, por dentro, un body:
un objeto invisible que Phaser usa para posición,
velocidad, y colisiones — es la caja invisible, ya calculada sola
Al tablero — collider: para lo sólido
function create() {
  personaje = this.physics.add.sprite(400, 300, "personaje");
  obstaculo = this.physics.add.sprite(600, 300, "personaje");

  this.physics.add.collider(personaje, obstaculo);
}
collider(a, b): "estos dos, de ahora en adelante,
no se pueden atravesar" — pared, plataforma, enemigo sólido
Ojo con esto
Si siguen moviendo al personaje escribiendo x/y a mano
(como en su plantilla), el collider pierde la pelea
Cada cuadro Phaser los empuja fuera del obstáculo,
pero si la tecla sigue apretada, su código los vuelve a meter
— se ve como si no hubiera colisión
Al tablero — muevan el body, no el sprite
// antes: personaje.x -= 4;
personaje.body.setVelocity(-240, 0);

// sin tecla apretada, hay que volver a poner 0
personaje.body.setVelocity(0, 0);
setVelocity es en píxeles por segundo, no por cuadro
Con velocidad, el movimiento y las colisiones
los maneja el mismo sistema — dejan de competir entre sí
Al tablero — overlap: para lo que se recoge
function create() {
  moneda = this.physics.add.sprite(500, 300, "personaje");

  this.physics.add.overlap(personaje, moneda, recogerMoneda);
}

function recogerMoneda(personaje, moneda) {
  moneda.destroy();
}
overlap detecta el toque pero no empuja:
sirve para monedas, power-ups, zonas de meta
¿Cuándo usarían collider, y cuándo overlap?

collider para cosas sólidas que bloquean el paso. overlap para cosas que se recogen o activan sin bloquear.

Construyendo un nivel de verdad
Hasta ahora todo su juego vive en una sola pantalla vacía,
con 2 o 3 sprites sueltos
Un juego real tiene un nivel:
piso, paredes, plataformas, monedas, todo acomodado
La forma más común de construir eso
se llama tilemap: un mapa hecho de piezas repetidas ("tiles")
Verde = piso · Amarillo = moneda · Negro = vacío
En un estudio real, esto se arma con un editor
visual (Tiled) y se exporta como archivo de nivel
Hoy no vamos a usar Tiled
Con for (que ya conocen) y arrays (que vemos ahora, rápido)
podemos construir el mismo concepto, sin herramienta nueva Para después, si quieren el editor real: docs.phaser.io/phaser/concepts/tilemaps
Repaso relámpago: arrays
Al tablero
const colores = ["rojo", "verde", "azul"];
console.log(colores[0]);
console.log(colores[2]);
Un array es una lista ordenada de valores, uno detrás de otro
Cada posición se llama con un número, empezando en 0:
colores[0] es "rojo", colores[2] es "azul"
Paso 1: describir el nivel como datos
Al tablero
const nivel = [
  "0000000000",
  "0000000000",
  "0011110000",
  "1111111111",
];
Cada fila es una línea de texto:
"1" = hay piso, "0" = está vacío
Esto es exactamente lo mismo que el dibujo de hace un momento —
solo que escrito como datos que un for puede leer
Si cambian una "0" por una "1" en el array,
¿qué cambia en el nivel dibujado?

Aparece un bloque de piso nuevo en esa posición exacta — mover el nivel es editar texto, no reescribir código.
Paso 2: recorrer el array y crear los sprites
Al tablero — en create()
function create() {
  plataformas = this.physics.add.staticGroup();

  for (let fila = 0; fila < nivel.length; fila++) {
    for (let col = 0; col < nivel[fila].length; col++) {
      if (nivel[fila][col] === "1") {
        plataformas.create(col * 64 + 32, fila * 64 + 32, "personaje");
      }
    }
  }
}
staticGroup(): un grupo de sprites físicos que
nunca se mueven — ideal para piso y paredes
Dos for anidados, igual que cuando recorrían
filas y columnas — nada nuevo aquí, solo aplicado a un nivel
col * 64 + 32 y fila * 64 + 32 convierten
"columna 3, fila 2" en una posición real en píxeles,
asumiendo que cada tile mide 64x64
¿Por qué el for revisa nivel[fila][col] === "1"
en vez de === 1?

Porque el nivel se escribió como texto ("0000..."), y cada carácter dentro de un string se compara como texto, no como número.

Paso 4: monedas dentro del mismo nivel
Al tablero
const nivel = [
  "0000000000",
  "00M0000M00",
  "0011110000",
  "1111111111",
];

function create() {
  // ... plataformas y personaje ya creados arriba

  monedas = this.physics.add.staticGroup();
  puntaje = 0;

  for (let fila = 0; fila < nivel.length; fila++) {
    for (let col = 0; col < nivel[fila].length; col++) {
      if (nivel[fila][col] === "M") {
        monedas.create(col * 64 + 32, fila * 64 + 32, "personaje");
      }
    }
  }

  this.physics.add.overlap(personaje, monedas, recogerMoneda);
}

function recogerMoneda(personaje, moneda) {
  moneda.destroy();
  puntaje += 1;
  console.log(puntaje);
}
Mismo patrón: un carácter nuevo ("M") en el array,
otro for que lo lee, overlap en vez de collider
Esto es construcción progresiva: cada mecánica
nueva se agrega encima de la anterior, sin romper lo que ya había
