De image a sprite
La clase pasada dibujamos al personaje
con this.add.image
De hoy en adelante vamos a usar
this.add.sprite
Por ahora, los dos hacen exactamente lo mismo:
dibujan una imagen ya cargada, en una posición
Pero un sprite tiene algo extra:
puede tener animaciones, fotogramas que cambian con el tiempo
Y también es el tipo de objeto
que se puede conectar a la física, más adelante
Por eso empezamos con sprite desde ya,
aunque hoy solo muestre una imagen fija
para no tener que cambiar de vocabulario después
El código casi no cambia 
const personaje = this.add.sprite(400, 300, "personaje");
¿Cómo se mueve algo en pantalla?
En el fondo, una pantalla nunca "mueve" nada:
solo dibuja imágenes, muchas veces por segundo
Para que algo se vea en movimiento,
hay que dibujarlo en una posición nueva,
y borrar el dibujo anterior
Eso es exactamente lo que hace update():
se repite sin parar, cuadro a cuadro
Y en cada cuadro, nosotros decidimos:
¿en qué posición se dibuja esta vez?
¿Cómo se imaginan que se mueve
un objeto en un videojuego?
Hay más de una forma de lograrlo:
con un motor de física
(eso lo vamos a ver más adelante),
o haciéndolo nosotros mismos, a mano
Hoy lo vamos a hacer a mano:
nosotros decidimos cuánto cambia
la posición, en cada cuadro

addKey crea una sola tecla,

Al tablero
function update() {
  if (Phaser.Input.Keyboard.JustDown(teclaEspacio)) {
    personaje.setTint(Phaser.Math.Between(0, 0xffffff));

JustDown(tecla): true solo
en el frame exacto en que se presiona
Aunque la mantengan apretada 3 segundos,
JustDown solo da true una vez
Por eso sí guardamos teclaEspacio

si la recrean cada vez, pierde esa memoria

útil como "feedback visual" instantáneo

Input de mouse
Phaser llama a todo (mouse, dedo, lápiz)
con el mismo nombre: pointer Documentación: docs.phaser.io/phaser/concepts/input
Eso significa que lo de hoy
funciona igual en un celular,
sin cambiar código
seguir el mouse
Al tablero
function create() {
  // ...
  const seguidor = this.add.sprite(100, 100, "personaje");
}

function update() {
  seguidor.x = this.input.activePointer.x;
  seguidor.y = this.input.activePointer.y;
}
this.input.activePointer siempre tiene
la posición más reciente del mouse
Poner esto en update() hace que el seguidor
se actualice constantemente, cuadro a cuadro

Clics
this.input.on("pointerdown", ...)
escucha clics en cualquier parte del juego
Hoy lo vamos a usar para algo nuevo:
teletransportar un objeto al punto donde clickean
Al tablero
function create() {
  // ...
  const marcador = this.add.sprite(400, 100, "personaje");

  this.input.on("pointerdown", (pointer) => {
    marcador.x = pointer.x;
    marcador.y = pointer.y;
  });
}
Esto se ve distinto a todo lo que
hemos escrito hoy — desarmémoslo
.on() es una función que tienen
los objetos de Phaser: significa "escuchar un evento"
Recibe 2 cosas: el nombre del evento
(un texto, "pointerdown"), y qué hacer cuando eso pase
Ese "qué hacer" es una función anónima:
sin nombre, escrita ahí mismo, como argumento
Es una función flecha, igual que las que ya vimos:
solo que en vez de guardarla en una variable, la mandamos directo
Y Phaser le manda un parámetro automático:
pointer, el clic que acaba de pasar
Adentro usamos pointer.x y pointer.y,
igual que siempre
Cada vez que hacen clic,
"marcador" salta a esa posición exacta

Arrastrar objetos
Hasta ahora el mouse "mueve otra cosa":
ahora va a mover directamente lo que clickean
Al tablero
function create() {
  // ...
  const arrastrable = this.add.sprite(200, 450, "personaje");
  arrastrable.setInteractive();
  this.input.setDraggable(arrastrable);
}
setInteractive() ya lo conocían:
lo hace clickeable
setDraggable además lo habilita
para arrastrar
Al tablero
this.input.on("drag", (pointer, gameObject, dragX, dragY) => {
  gameObject.x = dragX;
  gameObject.y = dragY;
});
Mismo patrón que el pointerdown de hace un momento:
otro evento, otra función anónima
Solo que ahora la función recibe
4 parámetros en vez de 1
El evento "drag" se dispara
mientras arrastran, con la nueva posición ya calculada
dragX y dragY:
a dónde se está moviendo el objeto en este instante
Ojo con esto
gameObject es un parámetro que Phaser envía solo:
les dice CUÁL objeto están arrastrando (útil si hay varios)

Apuntar hacia el mouse
Mecánica clásica de juegos de disparos
vistos desde arriba: el personaje mira hacia donde apunta el mouse
Para eso necesitamos un ángulo,
entre 2 puntos: el personaje y el mouse
Al tablero
function update() {
  personaje.rotation = Phaser.Math.Angle.Between(
    personaje.x, personaje.y,
    this.input.activePointer.x, this.input.activePointer.y
  );
}
Phaser.Math.Angle.Between recibe
2 posiciones (x1,y1 y x2,y2)
y devuelve el ángulo entre ellas, en radianes
personaje.rotation gira el sprite:
asignarle ese ángulo lo apunta hacia el mouse
No hace falta entender radianes hoy
Solo que Phaser ya hizo la cuenta por ustedes
Un dato para el que quiera ir más allá
En Unity, Unreal, o motores más "de verdad",
esto se hace con vectores, no con un atajo como Angle.Between
Ahí también hay librerías que lo simplifican
pero apoyarse en una que no entienden del todo
tiene un costo, más adelante
Si su juego termina con un bug de rotación raro
que no saben de dónde sale, lo más probable es que sea justo ahí:
un cálculo que nunca entendieron de verdad
Por eso, si van en serio con esto,
en algún momento vale la pena aprender
qué es un vector y cómo se calcula un ángulo a mano
