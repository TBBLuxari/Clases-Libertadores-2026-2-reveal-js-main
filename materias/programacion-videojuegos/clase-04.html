La clase pasada dejamos al personaje moviéndose con las flechas,
y ya sabe que no salirse del canvas gracias a Clamp
Hoy cambiamos de tema por completo:
colisiones
Y hoy sí, después de tanto rato mencionándolo,
conocemos por fin la física de Phaser
El problema
Imaginen que agregamos un segundo sprite
a nuestro juego: un obstáculo
Al tablero
function create() {
  personaje = this.add.sprite(400, 300, "personaje");
  cursors = this.input.keyboard.createCursorKeys();

  obstaculo = this.add.sprite(600, 300, "personaje");
}
Muevan al personaje encima del obstáculo,
con las flechas
¿Qué creen que va a pasar
cuando se toquen?
Nada. Absolutamente nada
El personaje pasa justo encima,
como si el obstáculo no existiera
Y tiene sentido: nosotros nunca le dijimos a Phaser
qué hacer cuando dos sprites se tocan
Para Phaser, cada sprite es solo
una imagen flotando en el aire, sin relación con las demás
¿Qué información necesitaríamos comparar
para saber si dos sprites se están tocando?
Sus posiciones.
Y algo más: su tamaño
La caja invisible
Aunque un sprite se vea como un personaje,
un enemigo, una moneda...
para el motor es, en el fondo, un rectángulo
Ese rectángulo se llama su
bounding box, o caja de colisión
Y para saber si dos sprites se tocan,
basta con revisar si sus dos cajas se solapan
a
b
Sin colisión: las cajas no se tocan en ningún eje
a
b
Con colisión: las cajas se superponen en X y en Y a la vez
Fíjense en esa palabra:
al mismo tiempo
No basta con que se toquen en X
también tienen que tocarse en Y, las dos cosas a la vez
Si dos cajas se tocan en X pero
NO en Y, ¿hay colisión?

No. Tienen que solaparse en los dos ejes.
Para calcular esto necesitamos
4 datos de cada sprite:
dónde empieza y dónde termina, en X y en Y
Y Phaser ya nos da 2 de esos datos gratis:
personaje.width y personaje.height
Al tablero
console.log(personaje.width);
console.log(personaje.height);
El ancho y el alto de la imagen, en píxeles
Con eso podemos calcular
los 4 bordes de la caja
Vamos a desarmarlo, borde por borde,
igual que hicimos con let vidas = 3
Al tablero
const izquierda = personaje.x;
El borde izquierdo es, simplemente,
la posición x del sprite
Al tablero
const derecha = personaje.x + personaje.width;
El borde derecho es la posición x,
más el ancho
¿Por qué hay que sumarle el ancho,
y no solo usar x?

Porque x es donde EMPIEZA el sprite: sin sumar el ancho, el borde derecho quedaría en el mismo punto que el izquierdo.
Al tablero
const arriba = personaje.y;
const abajo = personaje.y + personaje.height;
Mismo patrón, en el eje vertical
Con los 4 bordes de cada sprite,
ya podemos comparar
Vamos a armar una función que reciba
2 sprites, y devuelva true o false:
¿están chocando o no?
Al tablero
function hayColision(a, b) {

}
El esqueleto: recibe dos sprites, a y b
Adentro necesitamos revisar 2 cosas:
que se toquen en X, y que se toquen en Y
Para tocarse en X, el borde izquierdo de uno
tiene que estar antes del borde derecho del otro
y viceversa
Al tablero
function hayColision(a, b) {
  const tocaEnX = a.x < b.x + b.width && a.x + a.width > b.x;
}
Desarmemos esa línea:
a.x < b.x + b.width: el borde izquierdo de a
está antes de donde termina b
a.x + a.width > b.x: el borde derecho de a
está después de donde empieza b
Si las dos son true,
a y b se están tocando en el eje X
Ahora lo mismo,
pero en Y
Al tablero
function hayColision(a, b) {
  const tocaEnX = a.x < b.x + b.width && a.x + a.width > b.x;
  const tocaEnY = a.y < b.y + b.height && a.y + a.height > b.y;
}
Y, como dijimos, solo hay colisión
si las dos son true al mismo tiempo
Al tablero
function hayColision(a, b) {
  const tocaEnX = a.x < b.x + b.width && a.x + a.width > b.x;
  const tocaEnY = a.y < b.y + b.height && a.y + a.height > b.y;
  return tocaEnX && tocaEnY;
}
Esta técnica tiene nombre: colisión AABB
(Axis-Aligned Bounding Box), cajas alineadas a los ejes
No necesitan memorizar el nombre
Sí necesitan entender la idea: comparar bordes
Y esta misma función les sirve
para siempre, sin importar qué sprites sean
Ejercicio: agreguen la función hayColision(a, b)
completa a su main.js, fuera de create() y update()

10 minutos, a escribirla
Usarla en update()
Ya tenemos la función
Ahora hay que preguntarle, en cada frame,
si personaje y obstaculo están chocando
Al tablero
function update() {
  if (hayColision(personaje, obstaculo)) {
    personaje.setTint(0xff0000);
  } else {
    personaje.clearTint();
  }
}
setTint(0xff0000) lo pinta de rojo
clearTint() le quita el color
Así, mientras se están tocando,
el personaje se pinta de rojo
en cuanto se separan, vuelve a la normalidad
Ejercicio: agreguen ese if a su update(),
y prueben mover el personaje sobre el obstáculo
A probarlo
Eso ya es una colisión de verdad:
el juego sabe cuándo dos objetos se tocan
Pero fíjense: solo estamos detectando
el personaje se sigue atravesando,
solo que ahora se pone rojo mientras lo hace
Que no se atraviesen de verdad
Detectar es la mitad del problema
La otra mitad es reaccionar: empujar al personaje
para que no se meta
Esto ya no es una sola regla
Depende de por dónde chocó
Si el personaje viene desde la izquierda
y choca con el obstáculo, ¿hacia dónde
hay que empujarlo de vuelta?

Hacia la izquierda: justo antes del borde izquierdo del obstáculo.
Al tablero
if (hayColision(personaje, obstaculo)) {
  personaje.x = obstaculo.x - personaje.width;
}
Si viene de la izquierda, lo dejamos
pegado justo antes del obstáculo
Pero eso solo cubre un lado
Si viene por la derecha, por arriba o por abajo,
necesitan una cuenta distinta para cada caso
Y hay que decidir, con más ifs,
desde qué lado vino exactamente, comparando
qué tan metido está en cada eje
Esto empieza a sonar parecido
a algo que ya vieron...
¿A qué se parece esto?

Al Phaser.Math.Clamp de la clase pasada: ahí también sumaban o restaban posición para no salirse de un límite.
La diferencia es que el borde del canvas
nunca se mueve
un obstáculo sí, y si además se mueve, hay que
actualizar las cuentas en cada frame, para los dos
Reto (opcional): si les alcanza el tiempo,
intenten resolver el empuje para los 4 lados:
izquierda, derecha, arriba y abajo
5 minutos, a intentarlo
¿Por qué nadie hace esto a mano?
Con 2 objetos, ya es bastante código
para resolver bien los 4 lados
Ahora imaginen un juego con
10 enemigos, monedas, paredes, plataformas...
Cada par de objetos necesitaría
su propia comparación
eso crece muy rápido
Y hay más problemas escondidos: objetos que se mueven
muy rápido pueden "saltarse" el chequeo
entre un frame y el siguiente
O formas que no son rectángulos perfectos,
como círculos o polígonos
Por eso, casi ningún juego real
calcula colisiones a mano
existen motores de física para resolver justo esto
Y Phaser trae uno integrado,
listo para usar
Antes de conocerlo,
un respiro

Arcade Physics
Phaser trae un motor de física integrado,
pensado para juegos 2D simples y rápidos:
Arcade Physics Documentación: docs.phaser.io/phaser/concepts/physics/arcade-physics
Con él, todo lo que armamos a mano
hace un momento, Phaser ya lo resuelve por nosotros
Pero primero hay que encenderlo,
en el objeto config
Al tablero
const config = {
  type: Phaser.AUTO,
  width: 800,
  height: 600,
  physics: {
    default: "arcade",
    arcade: {
      gravity: { y: 0 },
      debug: false
    }
  },
  scene: { preload: preload, create: create, update: update }
};
default: "arcade" le dice a Phaser
qué motor de física usar
por ahora, el único que van a necesitar
gravity: { y: 0 } significa que,
por ahora, no hay gravedad
nadie cae solo
Eso lo van a cambiar más adelante,
cuando trabajen con plataformas
debug: false sirve para dibujar (o no)
las cajas de colisión en pantalla
muy útil mientras programan, se apaga al final
Si ponen debug: true mientras prueban su juego,
¿qué creen que van a ver dibujado sobre cada sprite?

Un rectángulo (o círculo) verde: exactamente la caja de colisión que antes calculábamos a mano.
Sprites con física
Ahora, en vez de this.add.sprite,
vamos a usar this.physics.add.sprite
Al tablero
function create() {
  personaje = this.physics.add.sprite(400, 300, "personaje");
  obstaculo = this.physics.add.sprite(600, 300, "personaje");
}
Se ve casi igual que antes
la diferencia está por dentro
Un sprite normal es solo una imagen
un sprite físico además tiene un body
El body es un objeto invisible que Phaser usa
para todos los cálculos: posición, velocidad,
y sí, colisiones
Ese body es, ni más ni menos,
la misma caja invisible que armamos a mano
solo que ahora Phaser la calcula sola
Por fin conocemos
el body del que hablamos hace dos clases
this.physics.add.collider
Con los sprites ya convertidos en físicos,
agregar la colisión de verdad
es una sola línea
Al tablero
function create() {
  personaje = this.physics.add.sprite(400, 300, "personaje");
  obstaculo = this.physics.add.sprite(600, 300, "personaje");

  this.physics.add.collider(personaje, obstaculo);
}
Documentación de colliders: docs.phaser.io/phaser/concepts/physics/arcade-physics
this.physics.add.collider(personaje, obstaculo):
"estos dos objetos, a partir de ahora,
no se pueden atravesar"
Eso es todo
ni funciones, ni bordes, ni ifs
Phaser hace, en cada frame, lo mismo que armamos a mano
Ejercicio: cambien this.add.sprite por
this.physics.add.sprite en su create(), agreguen
physics al config, y una línea de collider
A probarlo: muevan el personaje contra el obstáculo
Esta vez, de verdad, no se atraviesa
se queda pegado, como si chocara contra algo sólido
Prueben también poner debug: true en el config,
y miren la cajita verde sobre cada sprite mientras juegan
5 minutos, a probarlo
this.physics.add.overlap
A veces no queremos que los objetos
choquen como paredes
solo queremos saber que se tocaron
Piensen en una moneda: el personaje
camina sobre ella, no rebota contra ella,
la recoge
Para eso existe this.physics.add.overlap,
en vez de collider
Al tablero
function create() {
  moneda = this.physics.add.sprite(500, 300, "personaje");

  this.physics.add.overlap(personaje, moneda, recogerMoneda);
}

function recogerMoneda(personaje, moneda) {
  moneda.destroy();
}
overlap recibe un tercer argumento:
una función que se llama justo cuando
los dos objetos se tocan
moneda.destroy() elimina el sprite del juego
por completo, como si nunca hubiera existido
Fíjense: overlap detecta el toque,
pero NO empuja a nadie
los objetos pueden seguir superpuestos sin problema
¿Cuándo usarían collider,
y cuándo overlap?

collider para cosas sólidas (paredes, plataformas, enemigos que bloquean el paso). overlap para cosas que se recogen o activan (monedas, power-ups, zonas de meta).
Ejercicio: agreguen una moneda con overlap,
que desaparezca cuando el personaje la toque
