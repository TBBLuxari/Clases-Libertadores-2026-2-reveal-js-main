Variable
Una variable es como una caja
con un nombre, donde guardamos información
Toda variable en JavaScript se escribe
siguiendo siempre la misma receta 
let vidas = 3;
Vamos a desarmar esta línea
pieza por pieza 
let vidas = 3;
let es una palabra reservada
le dice a JavaScript:
"voy a crear una caja nueva" 
let vidas = 3;
vidas es el nombre
que nosotros elegimos para esa caja 
let vidas = 3;
El signo = aquí no es "igual"
matemático, significa "guarda esto adentro" 
let vidas = 3;
Y el 3 es el valor
lo que de verdad queda guardado en la caja 
let vidas = 3;
Por último, el ;
le dice a JavaScript "esta instrucción terminó aquí"
Entonces, en resumen
let + nombre + = + valor + ; 
let nombreJugador = "Ash";
Misma receta, otro ejemplo:
let, nombre, =, valor, ;
Con let esa caja se puede
volver a llenar más adelante 
let vidas = 3;
vidas = 2;
vidas = 1;
Cada línea le cambia el valor
a la misma caja
Fíjense que en la línea 2 y la línea 3
no volvimos a escribir "let"
Eso es porque la caja ya existe
solo estamos cambiando lo que hay adentro
¿Qué creen que pasa si escriben
let vidas = 3; y luego otra vez
let vidas = 5; (con let las dos veces)?
Error: la variable ya existe
Pero a veces queremos una caja
que nunca cambie de valor
Por ejemplo, la gravedad de nuestro juego:
no tiene sentido que cambie a mitad de partida 
const gravedad = 9.8;
const crea una caja fija
misma receta, solo cambia la primera palabra
Si intentan cambiarla después,
JavaScript no los deja 
const gravedad = 9.8;
gravedad = 20;
Eso tira un error como este 
Uncaught TypeError: Assignment to
constant variable.
Regla práctica
Si el valor va a cambiar, usen let
si no, usen const
El nombre de su personaje no va a cambiar
durante el juego, ¿usarían let o const?
const

vidas y Vidas

Tipos de dato
No todo lo que guardamos
en una caja es del mismo tipo 
let vidas = 3;
Esto es un number:
cualquier número, con o sin decimales
Con los number se pueden hacer
las operaciones matemáticas de siempre 
3 + 2   // 5
5 - 1   // 4
2 * 4   // 8
10 / 2  // 5
+ - * /: suma, resta,
multiplicación y división 
let nombre = "Ash";
Esto es un string:
texto, siempre entre comillas
Los string también se pueden
unir con el símbolo + 
let nombre = "Ash";
let saludo = "Hola " + nombre;
// saludo vale "Hola Ash"
A eso se le llama concatenar
Ojo con esto
Si mezclan number y string con +,
JavaScript convierte todo a texto 
"Vidas: " + 3
// "Vidas: 3" (string, no number)
let estaVivo = true;
Esto es un boolean:
solo puede valer true o false
Los boolean casi nunca
los escriben ustedes a mano
Normalmente salen solos,
como resultado de comparar dos valores
(ya vamos a ver eso)
Y hay un tipo más
¿Qué pasa si declaran una variable
sin darle valor? 
let puntaje;
console.log(puntaje);
// undefined
undefined significa
"esta caja existe, pero está vacía"
Ojo con las comillas
"3" es un string
3 (sin comillas) es un number
y Phaser los trata distinto
Para saber de qué tipo es algo,
JavaScript tiene una palabra especial: typeof 
typeof vidas
// "number"
typeof nombreJugador
// "string"

Objeto
Un objeto es una caja
que adentro tiene varias etiquetas
cada una con su propio valor 
let personaje = {
  nombre: "Ash",
  vidas: 3,
  estaVivo: true
};
Cada etiqueta: valor se llama
una propiedad del objeto
Y fíjense: cada propiedad puede ser
de un tipo distinto: number, string, boolean...
Para leer una propiedad,
se usa un punto después del nombre del objeto 
console.log(personaje.nombre);
// "Ash"
personaje.nombre:
"de personaje, dame su nombre"
Y para modificar una propiedad,
se hace igual que con una variable normal 
personaje.vidas = 2;
console.log(personaje.vidas);
// 2

Comparar valores
Para que el juego tome decisiones,
primero necesita comparar valores 
vidas > 0
vidas === 0
vidas <= 3
Estas comparaciones no guardan nada,
solo responden true o false
  1. > <: mayor que, menor que
  2. >= <=: mayor o igual, menor o igual
  3. === !==: igual, distinto
Importante
=== compara si son iguales
(con dos = se lo asignan a una caja, no comparan)
Y por qué === con 3 signos,
y no == con 2 
"3" == 3    // true
"3" === 3   // false
== convierte tipos antes de comparar
=== exige que sean del mismo tipo también
Por eso
en este curso vamos a usar siempre ===,
así evitamos sorpresas
A veces necesitamos combinar
más de una comparación a la vez
Para eso existen los operadores lógicos:
&& (y) y || (o) 
vidas > 0 && estaVivo
// true SOLO si las dos son true
Con &&, ambas condiciones
tienen que cumplirse 
vidas === 0 || !estaVivo
// true si con que UNA sea true
Con ||, alcanza con que
una sola sea true
Si vidas vale 0 y estaVivo es true,
¿qué da vidas > 0 && estaVivo?
false

if / else
Un if es un bloque de código
que solo se ejecuta si algo es cierto
Al igual que con las variables,
un if siempre tiene la misma forma 
if (vidas <= 0) {
  console.log("Game over");
}
Vamos a desarmarlo pieza por pieza,
igual que hicimos con la variable 
if (vidas <= 0) {
  console.log("Game over");
}
La palabra if significa "si":
le dice a JavaScript "revisa esto primero" 
if (vidas <= 0) {
  console.log("Game over");
}
Adentro de los paréntesis va la condición:
la pregunta que se responde true o false 
if (vidas <= 0) {
  console.log("Game over");
}
Y adentro de las llaves { } va
lo que pasa SOLO si la condición fue true
Entonces, en resumen
if + (condición) + { qué hacer }
Si vidas <= 0 es true,
se ejecuta lo de adentro de las llaves
¿Y si la condición es false?
Sin un else, JavaScript
simplemente no hace nada, y sigue de largo
Y si queremos que pase otra cosa
cuando NO se cumple, usamos else
else significa "si no, entonces..."
y siempre va justo después del if 
if (vidas <= 0) {
  console.log("Game over");
} else {
  console.log("Sigues vivo");
}
Si vidas vale 2,
¿qué mensaje se imprime?
"Sigues vivo"
A veces hay más de dos caminos
posibles, no solo "sí" o "no"
Para eso existe else if:
agrega una condición extra, entre el if y el else 
if (vidas === 0) {
  console.log("Game over");
} else if (vidas === 1) {
  console.log("Cuidado, casi sin vidas");
} else {
  console.log("Todo bien");
}
JavaScript revisa de arriba hacia abajo,
en orden
En cuanto encuentra una condición true,
ejecuta ese bloque y se detiene ahí,
no revisa las demás
Si vidas vale 1,
¿cuál de los 3 mensajes se imprime?
"Cuidado, casi sin vidas"
Y como ya vimos && y ||,
también los podemos usar dentro de un if 
if (vidas > 0 && estaVivo) {
  console.log("Puede seguir jugando");
}

Extra: si les alcanza el tiempo,

for
Imaginen que quieren imprimir
100 mensajes en la consola
¿Van a escribir console.log 100 veces,
uno debajo del otro?
Para eso existe el for:
repite un bloque de código varias veces,
sin copiarlo y pegarlo 
for (let i = 0; i < 5; i++) {
  console.log(i);
}
Se ve raro al principio,
vamos a desarmarlo en sus 3 partes 
for (let i = 0; i < 5; i++) {
  console.log(i);
}
let i = 0: se ejecuta
una sola vez, al principio de todo
Crea una variable nueva, i,
que actúa como contador del bucle 
for (let i = 0; i < 5; i++) {
  console.log(i);
}
i < 5: se revisa
antes de cada vuelta
Si es true, el bucle sigue
si es false, el bucle se detiene 
for (let i = 0; i < 5; i++) {
  console.log(i);
}
i++: se ejecuta
después de cada vuelta
i++ es una forma corta de escribir
i = i + 1: le suma 1 a i
Entonces, en resumen
dónde empieza · hasta cuándo repetir · qué cambia cada vuelta
Ese código se repite 5 veces,
imprimiendo 0, 1, 2, 3, 4
Ojo con esto
Empieza en 0, no en 1,
y para antes de llegar a 5
Un peligro real
¿Qué pasa si se les olvida
el i++? 
for (let i = 0; i < 5; ) {
  console.log(i);
}
i nunca cambia,
la condición nunca se vuelve false
Eso se llama bucle infinito:
el navegador se cuelga, y hay que cerrar la pestaña
[ meme/video aquí: sobre bucles infinitos / el navegador colgado ]
Por eso, cada vez que escriban un for,
revisen que las 3 partes estén completas
También pueden cambiar de a cuánto salta
el contador en cada vuelta 
for (let i = 0; i < 10; i += 2) {
  console.log(i);
}
// 0, 2, 4, 6, 8
i += 2 suma de 2 en 2,
en vez de ir de uno en uno
¿Les suena parecido a algo?
El game loop de la clase pasada
también es un bucle que se repite
Solo que ese, Phaser ya nos lo escribió:
nosotros solo llenamos preload, create y update

Función
Una función es un bloque de código
guardado, que no se ejecuta solo
hasta que alguien lo llama
Igual que con variable y con if,
una función siempre tiene la misma receta 
function saludar() {
  console.log("Hola!");
}
Vamos a desarmarla pieza por pieza 
function saludar() {
  console.log("Hola!");
}
function es la palabra reservada:
"voy a guardar un bloque de código" 
function saludar() {
  console.log("Hola!");
}
saludar es el nombre
que nosotros le damos a la función 
function saludar() {
  console.log("Hola!");
}
Los paréntesis ( ) son donde va
la información que la función necesita recibir
(aquí, por ahora, ninguna) 
function saludar() {
  console.log("Hola!");
}
Y las llaves { } son donde va
todo lo que la función hace cuando la llamen
Con eso solo la creamos
nadie la ha llamado todavía 
function saludar() {
  console.log("Hola!");
}

saludar();
Esa última línea es la que la ejecuta
de verdad
Ojo con esto
Si escriben saludar sin paréntesis,
no se ejecuta, solo la nombran
Las funciones también pueden
recibir información de afuera 
function saludar(nombre) {
  console.log("Hola " + nombre);
}

saludar("Ash");
nombre es un parámetro:
un valor que le pasamos al llamarla
Y pueden recibir más de uno,
separados por comas 
function presentar(nombre, edad) {
  console.log(nombre + " tiene " + edad);
}

presentar("Ash", 10);
Y también pueden devolver
un resultado, con return 
function sumar(a, b) {
  return a + b;
}

let resultado = sumar(2, 3);
resultado termina valiendo 5
¿Y si no ponen return?
La función igual funciona, pero
devuelve undefined
Hay más de una forma de escribir una función
esta se llama función flecha 
const saludar = (nombre) => {
  console.log("Hola " + nombre);
};
Hace lo mismo que function saludar(nombre) {...},
solo que se ve distinto
En Phaser van a ver las dos formas,
así que ya no les va a sonar raro
cuando aparezca una función flecha
Ejercicio: en la consola, escriban una función

Por ejemplo, una que reciba vidas
y devuelva true o false según si sigue vivo
Llámenla con distintos valores
y revisen que el resultado tenga sentido
